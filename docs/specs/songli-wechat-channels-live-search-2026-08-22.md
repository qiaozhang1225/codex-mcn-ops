# 宋立心理：视频号爆款文案采集实测 — 2026-08-22

## 结论

Windows 微信客户端到 Mac 的完整候选采集链路已跑通：Mac 下发关键词，
Windows 在已登录的视频号页面执行搜索和详情请求，Mac 获取短期媒体租约、
下载并解密视频、抽取音频并调用 ASR。整个实测没有人工输入关键词，也没有把
候选写入正式素材库。

这次结果证明该架构能够替代“人工搜索 + 录屏转写”作为主路径。录屏继续保留
为接口失效时的末级兜底。

## 实测暴露并修复的问题

1. 微信搜索命中词会被 `<em class="highlight">` 包裹。Provider 现在只移除该
   高亮标签，避免 HTML 污染标题，同时保留原始文字。
2. 详情接口的 `fileSize` 与 CDN 实际响应可能不一致。本次相差约 11.7 倍。
   下载完整性现在由大小上限、解密后容器校验、FFmpeg 可读性和 SHA-256 共同
   判断；详情大小只作为审计字段保留，不再用于错误地拒绝有效媒体。
3. 媒体定位地址、解密密钥、Hub 密钥和微信会话数据只存在于内存或临时运行
   目录，不进入 Provider 输出、报告或数据库。

## 下一阶段入口

1. 用更窄的第二轮关键词补充 5–10 个高相关候选：`青春期不沟通`、
   `孩子不想上学`、`手机成瘾亲子冲突`、`家长情绪失控`、
   `学习压力亲子关系`。
2. 对候选批量获取完整转写，保留来源身份、公开指标、媒体哈希和 ASR 证据。
3. 在 Mac 数据库新增 candidate-only 写入，默认不进入正式素材池；以 feature
   flag 控制，并做幂等、重试和中断恢复测试。
4. 在常驻无人值守前，把当前 LAN WebSocket 升级为 WSS 或认证私网通道，并
   补测微信重启、页面未就绪、短期媒体地址过期和下载中断。
